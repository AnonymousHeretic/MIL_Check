# 문서 기반 계약 검토 개발 순서

기준일: 2026-09-15. 과거 조항 예측 중심에서 계약 한 건의 검토 완료 중심으로 변경한다.
초기 시범 업무는 호환성·단독공급 사유의 물품 구매다. 실무자 확인 전 법적 지원 완료로 표시하지 않는다.

## 의존관계와 완료 조건

| 단계 | 선행조건 | 작업 | 완료 조건 |
|---|---|---|---|
| 0 | 없음 | 기준 버전/모델 보존, 단위시험·CLI 재실행, 데이터·라벨·위험 감사 | manifest 무결성 및 실행 증거. 내부 장비/사례 접근 여부는 미확정으로 명시 |
| 1 | 0 | 업무 흐름·공통 데이터 계약·모듈 경계·학습/평가/반입 구조 설계 | architecture.md, contracts.md, evaluation-plan.md로 구현 책임과 게이트 정의 |
| 2 | 0~1 | 공개 데이터 확장, 문서·희소 유형·정답 구축, 시험세트 고정 | 출처/이용조건/묶음 중복 제거/시점/라벨 성격과 분모 확인 |
| 3 | 2 | 작은 추출·검색 실험, 실제 대상 장비 측정 | 기존 n-gram/규칙 추출과 LLM·의미 검색의 품질·시간·메모리 비교 |
| 4 | 1~3 | 공통 계약 구현, legacy 변환, 확인 경계와 B01~B04 수정, 최초 사례 연결 | 원문→후보→질문→확인→검사→보고서 전 구간 시험 |
| 5 | 4 | 증빙 대조·근거 버전·이력 후보 완전성·질문/보고서 개선 | B05~B11 시험, Advisor 없는 흐름, 중요 누락/수정량 평가 |
| 6 | 3~5 | 필요성이 입증된 모델 학습, 패키징·반입 전후 비교 | 모델/규칙/색인/스키마 고정, 오프라인 설치 및 되돌리기 검증 |

| 8 | 7 또는 제한 명시 | 검증된 기능 배포·운영 기록·개발계획서/발표 정리 | 공개 검증과 군 실증을 구분, 미완료 범위와 실증 의존성 공개 |

내부 담당자·데이터 사용·장비 협의는 단계 0부터 병행한다. 승인 지연 시 단계 7을 완료 처리하지 않는다.
단계 1의 공통 데이터 계약은 모델 선정 전에 정의한다. 단계 3 실험 코드가 별도 제품 경로로 굳어지지 않도록 단계 4에서 어댑터로 연결한다.

## 데이터 확장과 학습

- 기획서 수치: 전체 계약 37,595건, 조항 기재 30,059건. 원본 재수집 시 실제 수를 다시 계산한다.
- 과거 기재 조항은 적정성 정답이 아니다. 전문가 검증 라벨과 구분하며 소급 법령 적용을 방지한다.
- 우선순위: 방위사업청 추가 시기/기관·입찰 연결→나라장터 물품/용역→공개 공고문/규격서/서식→현행·연혁 규정→감사/해석 및 전문가 정답.
- 국가/지방 등 적용 체계, 업무 유형, 시점, 부서, 품목을 보존한다. 다른 체계의 라벨을 그대로 합치지 않는다.
- 5천/1만/2만/가용 전체의 학습곡선과 희소 유형 성능으로 추가 수집 효과를 판단한다. 수량 자체를 목표로 삼지 않는다.
- LLM 사전학습을 처음부터 수행하지 않는다. 사전학습 모델의 무학습 기준선→공개 문서 추출/질문 데이터 조정→필요 시 추가학습 순서다.
- 합성 자료는 경계/오류 회귀에 쓰며 실제 군 성능 정답으로 계산하지 않는다. 교사 모델 생성 결과는 전문가 검토 전 정답이 아니다.
- 최신 법령·내부 이력은 버전 있는 규칙/검색으로 갱신한다. 내부 인덱스 갱신을 가중치 학습으로 표현하지 않는다.

## 비교실험

검색은 법령 참고/유사계약/분할 후보 확보를 별도 평가한다. 정확 조문 조회는 순위 검색과 분리한다.
n-gram, 의미 검색, 결합, 재정렬을 같은 자료로 비교하고 새 점수에 기존 0.30/0.45/0.70 임계값을 복사하지 않는다.
과거 조문·부정·근거 없음·복수 근거·동명 다른 규격을 포함한다. 분할은 top-k 대신 합산 대상 누락/과포함을 측정한다.
LLM은 텍스트 PDF의 사실/출처/질문부터 시험한다. OCR/HWP는 실제 파일 확보 후 별도 측정한다.

로지스틱 회귀 Advisor는 제품 핵심에서 제외한다. 표시/비표시 비교에서 업무 효용이 없으면 새 흐름에서 제거한다.
기존 모델 파일과 실행 경로는 비교·복구용으로 보존한다. LLM/임베딩 후보 선정은 미완료이며 배포 기본값으로 켜지 않는다.

## 점진적 이행과 PR 단위

설계·보존 검사(본 PR)→데이터/평가 세트→비교실험→공통 계약/확인 경계→최초 문서 검토 흐름→이력/근거→통합/반입→내부 실증.
각 PR은 변경 후 동작·영향 모듈·근거 있는 시험·남은 한계를 적는다. 의도적 버그 수정의 결과 차이는 별도 기록한다.
색인/패키지는 새 버전을 별도 생성하고 검증 후 전환한다. 이전 모델/규칙/색인과 새 사용자 기록의 롤백 호환성을 시험한다.
본 PR의 보존 검사는 단계 0~1 전용이다. 후속 제품 수정에서는 보존 브랜치를 유지한 채 허용 변경과 새 기준선을 리뷰한다.

접수 전 목표는 단계 0~1 및 확보 가능한 소규모 검증이고, 발표 전 목표는 최초 업무의 검증 가능한 흐름이다.
