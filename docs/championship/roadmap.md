단계 2의 실험용 구현은 제품의 상세 인터페이스를 미리 확정하지 않는다.
동일 기능을 둘 이상의 경로에서 중복 구현하지 않고 단계 3에서 연결한다.

## 단계 2 실험 규약

### 검색

별도 과제로 비교: 법령 참고 검색 / 유사계약 / 분할 후보 확보.
기준: 현재 n-gram. 후보: 의미 검색, 결합 검색, 재정렬.
정확한 조문 ID 조회는 검색 순위 성능과 별도로 시험한다.

평가 자료에는 유사 조문·과거 버전·부정 표현·근거 없음·복수 근거·규격 다른 동명 계약을 포함한다.
법령 검색은 사용자가 실제로 제공한 질의만 사용하는 시험과 규칙 결과를 이용하는 통합시험을 구분한다.
Recall/Hit/MRR의 정의·정답 복수 허용·무응답 처리·분모를 사전 명시한다.
분할 분석은 UI top-k 정확도 대신 합산 대상 누락·과포함과 시간/부서 경계로 평가한다.

점수 종류와 임계값은 모델·색인 버전마다 따로 보정한다.
근거 없는 답변·잘못된 시행 버전·기권 무시를 감점하며 지연·메모리·설치 크기도 보고한다.
결과가 비슷하면 운용 비용이 작은 방식을 선택한다. 우세가 불명확하면 현 기준을 유지하고 불확실성을 기록한다.

### 문서 추출

텍스트 PDF부터 비교한다. 금액·세금·수량·견적 수·업체·날짜·증빙별 정답과 원문 위치를 사람이 확인한다.
규칙 추출 / 소형 모델 보강을 같은 입력에서 비교하고, OCR은 스캔 자료를 별도 평가한다.
출처 없는 값, 예정 증빙의 완료 처리, 파일과 대상의 불일치는 별도 오류로 집계한다.
기본형·확장형 후보 장비의 CPU/RAM/GPU/OS·설치 권한은 측정 전에 기록한다.
예산·장비가 확보되지 않으면 후보 환경의 가정과 미측정 항목을 남긴다.

## 평가 데이터와 기록

- 기존/이미 확인한 실패 사례: 회귀용.
- 실험·임계값 선택 자료: 개발용.
- 최종 미사용 자료: 마지막 검증용. 읽고 튜닝하면 회귀/개발로 전환.
- 계약번호·변경차수·사업·시간 분할; 원본에 없는 식별자는 가용성 한계를 표시.
- 모델별 모집단·필터·학습·평가 수를 별도 기록. 기록된 조항과 법적 타당성 라벨 구분.
- 증빙 정밀도·재현율, 잘못된 통과, 기권률·기권 후 성능, 담당자 수정시간을 함께 측정.
- 환경 확보 후 단계 0 명령을 먼저 실행하고 실패를 기록한다.
- 기존 저장소 결과 파일을 덮어쓰지 않고 실행 버전별 결과를 보관한다.
- 최신 평가 결과를 향후 README·발표·개발계획서가 공유하도록 한다.

## 점진적 이행과 되돌리기

1. 기존 진입점을 유지한 채 legacy dict 변환기를 넣는다.
2. 대표 사례 하나에서 후보→확인→규칙→근거→보고서를 연결한다.
3. 신·구 경로를 동일한 확정 사실로 비교한다. 의도적 버그 수정은 차이 사유를 기록한다.
4. 유형별로 옮기고 단계마다 데이터·규칙·결과 버전을 남긴다.
5. 새 인덱스는 별도 생성·검증 후 전환한다. 생성 실패 시 직전 검증본을 유지한다.
6. 배포와 데이터 이행의 되돌리기를 구분한다. 새 버전에서 저장한 자료를 구버전이 읽을 수 있는지 검증한다.

## PR 분할 원칙

기준선/설계 → 실험 보고 → 공통 계약 → 확인 경계/추출 → 규칙/근거 → 이력/탐지 → 문서 AI → 통합/배포 순서로 나눈다.
각 PR은 문제·변경 후 동작·영향 받는 모듈·검증·남은 한계를 적고, 기능에 필요한 시험과 화면을 함께 변경한다.
핵심 수동 경로가 유지되는 단위로 병합한다. 미검증 모델을 기본 설정으로 켜지 않는다.

## 미해결 확인 항목

- 실제 대상 장비·설치 권한·허용 모델 및 반입 절차.
- 실무자 및 검증 가능한 비식별 사례 확보.
- 제출 당시 버전과 저장소 버전의 연결.
- 규정별 적용 시점·예외·지원 깊이의 전문가 확인.
- 단계 2 결과에 따른 상세 스키마 및 저장 방식.
- 대회 서류는 기술 기록을 기반으로 별도 작성한다. 접수 마감 전 완료분과 이후 개발분을 구분한다.
