# 챔피언십 기술 개발: 단계 0~1

기준일: 2026-09-14
상태: 기준선 기록 및 목표 아키텍처 설계. 제품 기능 변경은 후속 단계에서 수행한다.

이 문서는 대회 제출용 개발계획서가 아니라 저장소 내부의 기술 개발 기준이다.

## 읽는 순서

1. [현재 구조와 기준선](baseline.md): 기준 커밋, 코드 의존관계, 확인된 위험과 재실행 절차.
2. [목표 아키텍처](architecture.md): 운용 환경, 모듈 경계, 검색 역할, 권한 및 장애 정책.
3. [후속 실행 순서](roadmap.md): 비교실험부터 구현·검증까지의 의존관계와 완료 조건.
4. [기준 파일 명세](baseline-manifest.json): 기존 저장소 파일의 Git blob 식별자와 크기.

## 이번 변경의 범위

- 단계 0: 현재 main의 커밋·전체 파일 식별자 보존, 실제 코드 기반 의존관계와 검증 공백 기록.
- 단계 1: 목표 업무·운용 형태·기능 경계·실패 시 동작 설계.
- 단계 2 이후: 검색·문서 추출 실험, 상세 스키마 확정, 제품 코드 변경, 평가 재실행.
- 과거 제출 당시 코드와 현재 기준 버전의 동일성은 아직 확인하지 않았다.
- 모델 선정·규정의 법적 타당성·실제 군 설치 승인을 완료한 것으로 해석하지 않는다.

## 검증 상태

이 PR에서는 고정 커밋의 GitHub 소스·파일 트리를 읽고 문서의 경로·기호·의존관계와 변경 범위를 확인했다.
현재 실행 환경을 사용할 수 없어 Python 테스트, 모델 재학습, 오프라인 설치는 이번 PR에서 실행하지 않았다.
기존 보고서의 수치는 역사적 기록이며 새 기준선 측정 결과가 아니다.
