# 외부 학습·내부 검증 평가 계획

상태: 단계 1 설계. 내부 데이터/장비/실무자와 목표치는 아직 확보·합의되지 않았다.
기존 unittest/CLI 평가와 신규 업무 효용·군 실증을 구분한다.

## 데이터 분리와 정답

계약 실무자 2인 독립 검토 후 불일치를 조정한다. 판단 불가능·지원 범위 밖도 라벨로 남긴다.
과거 기재 조항/전문가 적정성/문서 추출/증빙 충분성/검색 관련성 라벨을 서로 대체하지 않는다.
학습·개발(모델/임계값 선택)·미사용 최종 시험을 계약/사업/변경차수 단위로 분리하고 시간·기관 외삽을 따로 보고한다.
미래 계약·사후 증빙을 검토 당시 입력이나 검색 근거로 제공하지 않는다. 정상 분포 세트와 희소 위험 세트를 별도로 보고한다.
초기 내부 실제 사례 300~500건은 제안일 뿐 충분성 보장이 아니다. 유형별 위험 사례 수와 신뢰구간으로 보강량을 결정한다.
기존 30건 검색 및 이미 본 오류 사례는 회귀 자료로 보존하며 신규 일반화 시험처럼 제시하지 않는다.

## 비교군

A 기존 보존 버전 / B 문서 추출·질문·대조 흐름 / C B+내부 검색 / D 승인된 내부 보정·추가학습.
B에서는 n-gram/의미 검색과 Advisor 표시/비표시를 분리 실험한다. 한꺼번에 바꿔 원인을 혼동하지 않는다.
최종 후보 선정은 개발 세트에서만 수행한다. 시험 결과를 보고 튜닝했다면 해당 시험은 개발 자료로 전환한다.

| 영역 | 지표·분모 | 반드시 함께 기록 |
|---|---|---|
| 추출 | 필드별 정확 일치, 증빙 precision/recall | 오추출·누락, 세금/단가/수량 혼동, 출처 정확성 |
| 추천 | Top-3, Macro-F1, 조항별 재현율 | 과거 기재 예측임을 표시; 적정성으로 해석 금지 |
| 검색 | Recall@5, MRR, 잘못된 시행 버전 인용 | 복수 정답 정의, 근거 없음, 권한/시점 누출 |
| 점검 | 중요 오류 미탐/실제 중요 오류 수, 정상 건 오경고/정상 건 수 | 유형별 수·95% 신뢰구간. 희소 위험을 평균으로 숨기지 않음 |
| 기권 | 답변 수/전체 수 및 답변한 사례의 오류율 | 기권으로 숨긴 미탐, 기권 후 담당자 부담 |
| 보고서 | 근거 없는 주장/검토한 주장, 수정 필드·문장 수 | 누락된 중요사항과 원문 대조 |
| 업무 | 검토 완료시간, 보완 왕복, 중요 누락 | 사용자 숙련도, 비교 조건, 완료 여부 |
| 운영 | p50/p95 지연, 최대 메모리, 실패·복구, 설치 크기 | OS/CPU/RAM/GPU, 문서 길이, 동시 사용자 수 |

업무 비교는 난이도가 비슷한 서로 다른 사례를 사용자별 교차 배정해 같은 사례를 두 번 본 학습 효과를 줄인다.
목표는 중요 미탐을 악화시키지 않으면서 시간·수정량을 줄이는 것이다. 허용 오경고·기권·지연·비열등성 한도는 최종 시험 전에 실무자와 기록한다.
수치가 미합의이거나 표본이 부족하면 연구 결과로만 보고하며 운용 승인 근거로 간주하지 않는다.

## 내부 실행 프로토콜

1. 코드·모델·토크나이저·규칙·색인·스키마·설정의 버전/해시와 평가 도구를 묶어 반입한다.
2. 내부 검증 담당자가 개발자에게 공개하지 않은 시험세트로 실행한다. 고정 공개 스모크세트로 반입 전후 정합성도 확인한다.
3. 상세 입력·출력·오류·환경·지표를 내부에 저장한다. 담당자 검토와 조정 기록을 연결한다.
4. 외부 보고는 승인된 집계만 사용한다. 집계 반출이 불가하면 내부 확인 기록으로 대체한다.
5. 오프라인 설치, 외부 연결 차단, 손상/누락 패키지, 시간 초과, 이전 버전 복구를 시험한다.
6. 기준 통과 후에도 최초에는 기존 업무와 병행 관찰한다. 자동 승인·자동 결재에 연결하지 않는다.

내부 보정용 자료와 최종 시험세트를 분리한다. 운영자 수용/거부를 정답으로 자동 학습하지 않는다.
분포·기권·오경고·수정량 변화를 관찰하고 전문가 재검증 후 새 버전을 배포한다.
