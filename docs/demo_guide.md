# MIL-Check 시연 가이드

## 실행

```bash
python demo_app.py
```

브라우저에서 `http://127.0.0.1:8765`를 엽니다. Python 3.11 이상이면 실행할 수 있으며,
운영 핵심 경로는 외부 통신 없이 동작합니다.

## 발표용 화면 흐름

1. **시연 시나리오 선택**에서 사례를 선택합니다.
2. 화면의 **계약 상황 입력**을 확인합니다.
3. 자유서술을 직접 입력하면 먼저 **추출 결과 확인** 화면이 나타납니다.
4. 추출된 금액·유형·증빙을 담당자가 확인한 뒤 규칙 점검 결과를 설명합니다.
5. 최종 결과와 참고 신호를 구분해서 보여줍니다.

상단의 네 단계는 다음 의미입니다.

- 입력: 담당자가 계약 상황을 문장으로 입력
- 구조화 확인: 규칙/선택적 LLM이 추출한 필드를 담당자가 확인
- 규칙 점검: 법령 기반 결정론적 규칙 엔진이 검사
- 보고서: 누락 증빙·통제조건·참고 신호를 묶어 제시

## 권장 시나리오

### A. 정상 소액수의

1,800만 원의 일반 물품 구매 사례입니다. 금액 기준과 기본 증빙이 충족되는 흐름을
보여줍니다.

### B. 호환성 증빙 부족

기존 장비와 호환되는 부품을 특정 업체와 계약하려는 사례입니다. 장비 규격과 호환성
자료가 있어도 시장조사·대체불가성 분석이 빠지면 보완 필요로 표시되는 모습을 보여줍니다.

### C. 자체 지연을 긴급사유로 제시

내부 결재 또는 발주 지연으로 납기가 촉박해진 사례입니다. 긴급하다는 결과가 아니라
긴급성이 발생한 원인을 검사하고, 통상적인 행정지연은 부적합 사유로 표시합니다.

### D. 현재 범위 밖 공사

공사 계약을 입력하면 현재 MVP가 최종 판정하지 않는 범위로 안내합니다. 시스템이
모든 입력에 억지로 답하지 않고 전문 검토를 요구하는 안전장치입니다.

## 발표 중 강조할 문장

> MIL-Check는 계약을 자동 승인하지 않습니다. 규칙 엔진이 확인 결과를 만들고,
> ML·검색·LLM은 참고 신호와 문서화를 제공합니다. 최종 판단과 결재는 담당자에게 있습니다.

## 구현상 주의

- 자유서술 추출값은 확정값이 아니므로 반드시 담당자 확인 단계로 설명합니다.
- `PASS_WITH_CONTROLS`는 승인이나 적법성 확정이 아니라 “핵심 요건 충족·통제조건 이행 필요”입니다.
- 공개계약 추천·유사계약·가격대는 규칙 판정에 반영되지 않는 참고 신호입니다.
