# MIL-Check 시연 가이드

## 실행

```bash
python demo_app.py
```

브라우저에서 `http://127.0.0.1:8765`를 연다. Python 3.11 이상만 있으면 되고
인터넷 연결과 외부 패키지는 필요 없다.

## 권장 4분 시연 흐름

### 0:00–0:30 문제와 데이터

"군 계약 담당자는 한 건을 검토할 때 금액기준, 계약상대자 자격, 견적 절차,
수의계약 사유와 증빙을 여러 규정에서 확인해야 합니다. 저희는 방위사업청 공개
계약데이터 3만 7천 건을 분석했고, 그중 수의계약이 71.5%였습니다.
근거조항의 금액 상한과 실제 계약금액이 어긋난 건이 191건 있었습니다."

### 0:30–1:10 시나리오 A — 정상 소액수의

- 1,800만원 입력, 금액 기준 충족
- **근거조항 추천표**를 짚는다: 담당자가 제시한 조항이 모형 1순위와 일치하며 확률 62.4%
- 유사 공개계약 5건과 가격대가 함께 표시됨
- 규정 기준일 표시

### 1:10–1:50 시나리오 B — 호환성 증빙 부족

"특정 업체만 호환된다는 담당자의 주장만으로는 승인하지 않습니다.
독립 시장조사와 대체불가성 분석이 빠졌다고 표시합니다."

입력 JSON의 `objective_market_search` 또는 `no_substitute_analysis`를 증빙 배열에
추가하면 결과가 바뀌는 모습도 보여줄 수 있다.

### 1:50–2:25 시나리오 C — 자체 지연을 긴급사유로

"납기가 촉박하다는 결과가 아니라 원인을 봅니다. 통상적 행정지연이면 긴급수의
사유 자체가 부적합하다고 표시합니다."

동시에 ML 계층이 "유사한 품명·금액대는 제한경쟁으로 체결된 경우가 많다(92%)"는
신호를 내는 것을 함께 짚는다.

### 2:25–3:00 시나리오 D — 규칙은 통과, 데이터는 다른 이야기

"이 건은 규칙상 문제가 없습니다. 그런데 유사한 공개계약 5건 중 4건이 제한경쟁으로
체결되었습니다. 규칙만으로는 보이지 않는 구간이고, 이것이 AI 계층이 값을 더하는
지점입니다."

### 3:00–3:30 자유서술 입력

상단 입력창에 문장을 붙여넣는다.

> "기존 정수장비에 들어가는 부품인데 다른 회사 제품은 호환이 안 됩니다.
> 부가세 제외 4,600만원이고 가격조사와 자격 확인은 마쳤습니다."

추출된 필드 표가 먼저 나오고 검토 결과가 이어진다. 담당자는 JSON을 쓰지 않는다.

### 3:30–4:00 AI 구조와 보안

"학습은 공개망에서 scikit-learn으로 했고, 가중치를 JSON으로 내보내 폐쇄망에서는
표준 라이브러리만으로 추론합니다. 두 환경의 성능 차이는 Top-1 기준 0.18%p입니다.
반입 대상은 전부 합쳐 3.5MB이고, 군 내부 데이터는 학습에 쓰이지 않습니다.
판정은 규칙 엔진만 하고, AI는 추천·검색·탐지·문서화를 맡습니다."

## 심사 질문 대비

### AI가 아니라 단순 체크리스트 아닌가?

체크리스트는 규칙 엔진 한 계층이다. 그 위에 공개계약 3.7만 건으로 학습한
분류기 두 개(19클래스 Top-3 95.4%, 6클래스 Top-2 96.0%), 문자 n-gram 벡터 검색
(Recall@1 96.7%), 비지도 이상탐지(분할발주·가격·편중), 자유서술 필드추출이 있다.
법적 판정만 규칙에 맡긴 것은 설명가능성과 감사 추적을 위한 의도적 설계다.

### 정확도 78%면 낮은 것 아닌가?

19개 조항을 구분하는 문제이고 다수결 기준선이 62.4%다. Top-3으로는 95.4%이며,
시스템은 조항을 결정하지 않고 후보를 좁혀 제시한다. 확률 55% 미만이거나 1·2순위
격차가 20%p 미만이면 경고를 내지 않으므로, 낮은 확신이 잘못된 경고로 이어지지 않는다.

### 평가세트가 자체 제작이면 의미가 있나?

그래서 3층으로 분리했다. 자체 라벨 60건은 회귀 무결성 지표로만 쓴다. 성능 주장은
계약서에 기재된 실제 조항이 정답인 실데이터 300건과, 공개 감사보고서의 지적사항이
정답인 12건에서만 한다.

### 군 내부망에서 LLM을 어떻게 쓰나?

LLM 없이 모든 핵심 기능이 작동한다. 승인된 온프레미스 모델이 있으면 자유서술
이해와 보고서 문장 정리에만 쓴다. 필드추출 홀드아웃 실패 3건이 전부 표현 다양성
문제였기 때문에, 정확히 그 구간에만 LLM을 붙였다. 외부 상용 API는 기본안에서 제외했다.

### 탐지된 934건이 전부 위법인가?

아니다. 합산 시 상한을 넘는 유사 발주 후보이며, 작전 소요에 따른 정당한 분리발주가
포함될 수 있다. 감사원도 그늘막 22건 분할 사례에서 불가피성을 인정해 면책한 바 있다.
시스템은 확인을 요구할 뿐 판정하지 않는다.

### 누가 최종 책임을 지나?

MIL-Check는 승인 시스템이 아니다. 최종 판단과 결재는 계약담당공무원이 수행하며,
시스템은 적용 근거·누락 증빙·위험과 확인사항을 추적 가능한 형태로 제시한다.
