# MIL-Check 성능 측정 결과

기준일 2026-07-25 · 모든 수치는 `python -m milcheck.cli evaluate`와
`training/analyze_audit.py`로 재현할 수 있다.

측정 원칙은 세 가지다.

1. **자체 라벨과 외부 라벨을 분리한다.** 자체 라벨 성능은 회귀 무결성 지표일 뿐
   실제 정확도가 아니므로, 외부 라벨 지표와 섞어 제시하지 않는다.
2. **평가한 모델을 그대로 배포한다.** 전체 데이터로 재학습하지 않으므로 보고 지표가
   배포 모델의 성능과 정확히 일치한다.
3. **개발세트와 홀드아웃을 구분한다.** 규칙을 튜닝한 세트의 성능은 상한값으로만 쓴다.

## 2. AI 모델 성능 (외부 라벨)

학습은 공개망(scikit-learn), 추론은 폐쇄망(표준 라이브러리)에서 수행한다.
학습·평가는 8:2 층화분할이며, 아래 지표는 **학습에 쓰이지 않은 홀드아웃** 결과다.

|---|---:|

| 클래스 수 | 19개 조항 |
| Top-1 정확도 | **78.1%** |
| Top-2 정확도 | **92.0%** |
| Top-3 정확도 | **95.4%** |

다수결 기준선 대비 Top-1이 +15.7%p 높다. Macro F1이 0.544로 낮은 것은 소수
조항(연 20~60건 규모)의 재현율이 낮기 때문이며, 이 조항들은 확률이 낮게
나오므로 경고 임계값(확률 55% 이상, 1·2순위 격차 20%p 이상)에 걸리지 않아

## 3. 평가세트 3층 결과

### L1 — 규칙 회귀 (자체 라벨, 60건)

| 지표 | 값 |
|---|---:|
| 일치 | 60 / 60 |
| 잘못된 통과 | **0건** |

라벨을 규칙 설계자가 작성했으므로 **실제 정확도가 아니라 회귀 무결성 지표**다.
금액 상한 전후(19,990,000 / 20,000,000 / 20,000,001원), 견적 절차, 증빙
드롭아웃, 범위 밖 계약, 입력 오류를 포함한다.

### L2 — 실데이터 (외부 라벨, 300건)

학습에 쓰이지 않은 홀드아웃 계약에서 표본을 추출했다.

| 지표 | 값 |
|---|---:|
| 근거조항 Top-1 | 78.0% |
| 근거조항 Top-2 | 92.3% |
| 근거조항 Top-3 | 95.7% |
| 계약방법 Top-2 | 98.7% |

정답은 계약서에 기재된 실제 조항이며 MIL-Check가 만든 라벨이 아니다.
표본 지표(78.0%)가 전수 홀드아웃(78.1%)과 일치해 표본 편향이 없음을 확인했다.

### L3 — 감사사례 재현 (외부 라벨, 12건)

공개 감사보고서·법령해석의 지적사항을 정답으로 삼았다.

| 지표 | 값 |
|---|---:|
| 지적 유형 탐지 | 11 / 12 (91.7%) |
| 판정 일치 | 11 / 12 (91.7%) |

미탐 1건은 `AUD-008`(특별법 설립기관이라는 사실만으로 수의계약 근거를 주장한
사례)로, 현재 규칙이 "법인 성격"을 입력 필드로 받지 않아 열거주의 위반을
직접 지적하지 못한다. **알려진 한계로 기록한다.**

`AUD-011`(분할이나 불가피성 소명 가능), `AUD-012`(시행규칙 제33조 전자견적
예외)는 탐지에는 성공했으나 규칙이 면책·예외 사유를 반영하지 못한다는 점을
사례 안에 함께 기록해 두었다.

## 4. 근거검색 성능 (외부 라벨, 30건)

법령 용어가 아니라 실무자가 쓸 법한 구어체로 질의를 작성했다.
(예: "금액 맞추려고 사업을 여러 건으로 쪼개서 발주해도 되나")

| 방식 | Recall@1 | Recall@3 | MRR |
|---|---:|---:|---:|
| BM25 (어절) | 0.533 | 0.633 | 0.572 |
| **문자 n-gram (채택)** | **0.967** | **0.967** | **0.967** |
| RRF 하이브리드 | 0.700 | 0.867 | 0.772 |

**하이브리드가 더 나을 것이라는 가설은 기각되었다.** 한국어는 어미 변화 때문에
어절 단위 BM25의 어휘 일치가 자주 실패하고("호환성이 없는" vs "호환이 안 되는"),
RRF는 약한 검색기의 순위를 그대로 반영해 오히려 성능을 끌어내렸다. 세 방식을
모두 구현해 두었으므로 `--retrieval-mode`로 재현·검증할 수 있다.

조문 인용 질의("시행령 제26조제1항제5호가목")에서는 두 방식 모두 6/6으로 동일했다.

## 5. 필드추출 성능

| 세트 | 필드 단위 정확도 | 사례 완전일치 |
|---|---:|---:|
| 개발세트 30건 (규칙을 이 세트로 작성) | 100% | 100% |
| **홀드아웃 20건 (튜닝하지 않음)** | **87.9%** | **85.0%** |

홀드아웃 실패 3건의 원인은 다음과 같다.

| 사례 | 실패 원인 |
|---|---|
| EXH-01 | 한글 수사 표기("천사백만원")를 파싱하지 못함 |
| EXH-10 | "제조한 업체가 와서 직접 조립" — 우회 표현 미인식 |
| EXH-11 | "만드는 데가 한 곳뿐" — 유일공급 우회 표현 미인식 |

세 건 모두 **표현의 다양성** 문제이며 법적 판단 오류가 아니다. 이 지점이 승인된
내부망 LLM을 선택적으로 붙였을 때 실제로 값이 더해지는 구간이고, 규칙 추출기가
채우지 못한 필드에 한해 LLM이 보강하도록 설계한 근거다.

## 6. 공개계약 전수 적용 결과

정제된 37,595건 전체에 자체감사 규칙을 적용한 결과다.
**개별 건의 위법 여부를 단정하지 않으며, 담당자 확인이 필요한 후보를 뜻한다.**

| 검사 | 모집단 | 표시 | 표시율 |
|---|---:|---:|---:|
| 금액–근거 정합성 | 21,659건 | 191건 | **0.88%** |
| 분할발주 후보 | 16,884건 | 934건 (346개 묶음) | 5.53% |
| 가격 이상치 | 5,631건 | 96건 | 1.70% |
| 업체 편중 | 200개 부서 | 2개 부서 | 1.00% |
| 유사계약 가격대 산출 | 400건 표본 | 233건 | 58.2% (적용률) |

낮은 표시율이 중요한 이유는 **경고 과다가 이 종류 시스템의 주된 실패 원인**이기
때문이다. 금액 검사가 0.88%만 표시한다는 것은 담당자가 무시하지 않을 수준이라는
뜻이다.

### 측정 방법과 한계

- 추정가격은 공개 데이터에 없어 `계약금액 ÷ 1.1`로 근사했고, 상한 대비 3%
  초과 이탈만 집계했다.
- 분할발주 분석에서 조달청 위탁구매와 관급자재를 제외했다. 현장별 분리발주가
  정상인 항목이기 때문이다.
- 가격 이상치는 규격·수량 정보가 없어 단가가 아닌 총액 비교다. MAD가 0에
  가까울 때 z값이 폭주하는 문제를 로그 스케일 하한(0.05)으로 제어했다.
- 부서명은 SHA-256 별칭으로 치환했고 업체명·사업자등록번호·주소·담당자명은
  인덱스에 반입하지 않았다.

### 탐지 사례 (분할발주)

한 부서에서 42일 동안 여단별로 나눈 전투식량 구매 8건의 합계가 1억 950만원으로
소액수의 상한을 초과했다. 감사에서 반복적으로 지적되는 유형이다. 다만 작전
소요에 따른 정당한 분리발주일 수 있어 시스템은 확인을 요구할 뿐 판정하지 않는다.

## 7. 아직 측정하지 않은 것

다음은 실증 전이므로 수치를 주장하지 않는다.

- 실제 계약 실무자와의 판정 일치도
- 실제 검토시간 단축 폭
- 결재 전 보완 왕복 감소 폭
- 실제 감사 지적 예측력

이를 측정하려면 계약실무자 2인 이상의 독립 라벨링과 비식별 실사례 100건 이상이
필요하며, 추진 일정 4단계로 계획되어 있다.
